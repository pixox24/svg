# 参考图识别与分类分析

> 输入：`~/Desktop/参数化几何图形参考图/`（15 个文件，14 张独立图形 + 1 张重复/变体）
> 方法：逐张视觉识别 → 几何基元 / 排列规律 / 参数 / 配色 / 复杂度 / 家族归属
> 结论用途：推导参数化图形引擎的抽象模型与参数体系

---

## 0. 核心结论（先看这个）

**这 14 张图不是 14 个孤立的图案，而是同一套"参数化语言"的 14 个实例。**

它们共享一个统一的生成结构：

```
图形 = Lattice（底场） × Modulator（调制函数） × Primitive（基元） × Transform（变换） × Topology（拓扑） × Palette（配色）
```

只要把这 6 个正交维度参数化并允许自由组合，就能**还原全部 14 张参考图，并且能生成它们之外的无穷多新图形**——这正是"引擎"与"14 个硬编码图案"的本质区别。

因此引擎不应实现为「预设图案列表」，而应实现为 **可组合的参数管线（parametric pipeline）**：用户选底场 → 选调制 → 选基元 → 调变换 → 得到图形。预设只是参数的快照。

## 2. 六个正交维度（引擎的骨架）

### 2.1 Lattice 底场 —— "图形长在哪"

决定元素的**位置生成规则**。

| 类型 | 数学 | 覆盖参考图 |
|---|---|---|
| 正方网格 Cartesian | (i·d, j·d) | #02 #03 #07 #09 #10 |
| 六角/蜂窝 Hexagonal | 轴向坐标 (q, r) 双基向量 | #01 #04 #11 #12 #14 |
| 等轴测 Isometric | 正交双基向量 + 垂直轴 | #01 |
| 对角/斜交 Oblique | 双基向量夹角 ≠ 90° | #06 |
| 极坐标 Polar | (r, θ)，r 与 θ 独立参数化 | #08 #13 |
| Vogel 螺旋 | θ = n·α（α≈137.5°），r = c·√n | #05 #13 |
| 螺旋族 Spiral | r = k·θ（阿基米德）/ r = a·e^(bθ)（对数） | #08 #13 |
| 同心环 Ring | r = 常量序列 | #13 |
| 嵌套/二级 Hierarchical | 簇内底场 + 簇间底场 | #11 |

**参数**：类型、行列数 / 点数、间距、双基向量角度、原点、透视/斜切、二级底场配置。

### 2.2 Modulator 调制场 —— "什么在变"

决定**每个单元被什么函数扰动**。这是"参数化"的灵魂，也是参考图从"普通图案"升级为"高级图形"的原因。

| 类型 | 形态 | 覆盖参考图 |
|---|---|---|
| 常量 Constant | 全图均匀 | #01 #06 |
| 线性渐变 Linear | 沿某方向线性变化（尺寸/密度/间距） | #10 #12 |
| 径向渐变 Radial | 以某点为圆心渐变（暗角 / 透镜 / 隧道） | #02 #05 #08 |
| 正弦 Sine | A·sin(k·u + φ)，产生波腹/波节节奏 | #02 #07 #09 |
| 噪声 Noise | Perlin / Simplex，有机流动感 | #03 #10 |
| 黄金角 Golden | 无理数角增量，产生叶序 | #05 #13 |
| 逆向调制 Inverted | 值越大形越小（图底反转） | #02 |

**参数**：类型、作用轴/方向（X/Y/径向/角度/两者）、频率(zoom)、振幅(strength)、相位(offset)、基准值(bias)、随机种子(seed)。

> **关键洞察**：同一个底场换不同的调制函数，就得到完全不同的图形（#07 与 #09 都是"网格+正弦"，差异只在作用轴与基元大小函数）。**调制场的可组合性是引擎的主要威力来源。**

### 2.3 Primitive 基元 —— "画什么"

| 类型 | 覆盖参考图 |
|---|---|
| 圆点 Dot | #05 #07 #08 #09 #11 #13 |
| 椭圆 Ellipse（含长宽比 / 自转对齐切线） | #13 |
| 直线段 / 条形 Bar | #01 #06 #13 |
| 圆角矩形 / 胶囊 Capsule | #03 |
| 圆角多边形（三角形为主） | #12 |
| 曲边多边形（内凹六边形） | #04 |
| 路径段 Path / Arc（Truchet 弧） | #14 |
| 复合碎片 Fragment | #10 |

**参数**：类型、尺寸、长宽比、圆角半径、边数、曲率（内凹/外凸）、描边宽度、填充与否、旋转模式（无 / 切线对齐 / 径向对齐 / 跟随噪声场）。

### 2.4 Transform 基元变换 —— "怎么摆"

尺寸缩放、长宽比、旋转（含切线/径向对齐）、圆角、曲率、描边宽度、透明度、位移。

### 2.5 Topology 拓扑 —— "怎么连"

| 模式 | 说明 | 覆盖参考图 |
|---|---|---|
| 独立 Isolated | 单元之间无关联 | #02 #03 #05 #11 |
| 连通 Connected / Truchet | 依据规则（种子/噪声/固定模式）连接相邻单元的边，形成连续路径 | #01 #14 |
| 反向 Inverted | 正负形互换（图底反转），负空间成为主角 | #02 #04 #14 |
| 迷宫 Maze | 在底场上跑路径搜索算法（DFS 回溯）生成连通通道 | #01 |

### 2.6 Palette 配色 —— "什么颜色"

- 参考图 **13/14 为高对比双色**，1 张引入**单色锚点**（黑底 + 亮橙）
- 共同点：**去色彩化 + 强对比**，让视觉注意力落在结构与节奏上
- 引擎策略：以「前景色 / 背景色 / 强调色(accent)」三元组 + 反转开关为主，配合项目已有的调色板系统

## 3. 由抽象推导的引擎架构

```
参数 state
   │
   ▼
┌─────────────────────────────────────────────┐
│ 1. Lattice.resolve(params) → 单元位置数组    │  [{x, y, u, v, r, θ, i, j, n}]
│    每个单元携带归一化坐标 u,v ∈ [0,1] 与极坐标 r,θ   │
└─────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────┐
│ 2. Modulator.evaluate(cell, params) → m ∈ ℝ  │  归一化调制值（可多通道）
│    m 由底场类型 + 频率 + 振幅 + 相位 + 种子决定      │
└─────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────┐
│ 3. Primitive.render(cell, m, params) → path  │  把 m 映射到尺寸/长宽比/圆角/曲率/旋转
│    输出 SVG 路径数据（纯字符串，无 DOM）          │
└─────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────┐
│ 4. Topology.apply(paths, params)             │  连通/反转/迷宫；负空间处理
└─────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────┐
│ 5. Compose → <svg> 字符串                     │  含 viewBox / 背景 / 分组
└─────────────────────────────────────────────┘
   │
   ├──► 实时预览（DOM 注入，节流重绘）
   ├──► 导出 SVG / PNG / 复制代码
   └──► 预设 / 种子 / 分享链接（URL 编码参数）
```

**架构要点**

1. **纯函数管线**：`f(params) → svgString`。无副作用、可快照、可重放、可服务端渲染。
2. **与渲染解耦**：引擎不碰 DOM，只吐 SVG 字符串；预览层负责注入。这样才能同时服务「实时预览」和「批量导出」。
3. **参数即 state**：整套参数是一个扁平可序列化对象 → 天然支持预设、随机、撤销、URL 分享。
4. **可组合而非枚举**：新增图形 = 新增一个 Lattice 或 Modulator 或 Primitive 分支，而不是新增一个硬编码函数。

## 5. 与现有项目的关系

- 现有 `~/Desktop/svg`（SVG Playground）已具备：CodeMirror 编辑器、画布预设、调色板、导出、Tabler/Lucide 图标库、Tabbied 集成。
- **本引擎是"参数化"这一新的心智模型**：现有形态是「写 CSS/SVG 代码 → 看结果」，本引擎是「拖参数 → 看结果」。二者互补：**面板调出的参数，应当能一键转成编辑器里的 SVG 代码**——这是"连接现有功能"的核心抓手。
- 复用现有：导出模块、调色板 token、面板视觉语言、画布预设尺寸。
