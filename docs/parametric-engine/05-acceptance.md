## 一、结论摘要

**做了什么**：把「参数化图形生成」从 14 张参考图里**抽象成一件事**——底场 × 调制 × 基元 × 拓扑 × 配色，然后实现成一个可自由组合的引擎，并接进现有 Playground，自动继承了它全部基础设施（参数面板、实时预览、三种导出、侧栏、`?id` 分享、画布/DPI）。

**可以上线**。已知限制见第六节——都是明确记录的小事，没有阻断项。

## 四、架构决策：为什么最终只改了 1 行渲染逻辑

原 PRD 冻结的是"新增独立路由 + 自建 6 个 Svelte 组件 + 自建三栏 UI"。架构侦察后发现项目**已有 `system` 机制**（8 个引擎在用，`LookPanel` 本就是 schema 驱动的参数面板），于是改为接入既有机制。

| | 独立路由方案（原 PRD）| 接入 system 方案（已采纳）|
|---|---|---|
| 新增 Svelte 组件 | 6 个 | **0 个** |
| 新增路由 | 1 个 | **0 个** |
| 改动既有文件 | 多处 | `+page.svelte` **1 行** + 2 处追加式注册 |
| 与现有功能联动 | 需自行桥接 | **天然共享**：调色板/画布/DPI/导出/`?id`/变体切换 |

详见 `03b-architecture-decision.md`。**决定性理由**：需求原文是「跟项目中现有的功能连接起来，相互配合」——自建平行 UI 恰好违背这一点。

## 六、已知限制

1. **面板是扁平长列表，没有分组折叠。** `LookPanel` 的 schema 契约里没有分组概念，我用 `showIf` 控制可见字段数量来缓解（无条件时只显示约 20 项）。PRD 里"分组折叠"的愿望未实现。
2. **ref-01 是"等轴测迷宫"而非参考图的周期性 Y 形纹样。** 参考图是**平移对称**的规则纹样，而迷宫是 DFS 生成的非周期结构。两者共享同一套视觉语言（等轴测三向线、1:1 线宽间距）且密度一致（48.5% vs 51.4%），但严格说不是同一类图形。要精确还原需要给引擎加一个"周期性 Y 形基元"，属于引擎扩展。
3. **高覆盖率预设（如 ref-01，51%）在缩略图尺寸下会读成一片密实纹理。** 参考图本身也是如此（48.5% 墨量），不是缺陷，但侧栏小图辨识度有限。
4. **未做 PNG 多倍率导出。** 现有导出按钮走项目的 `svgToPngBlob`（默认长边 2048），我没有另加 1x/2x/4x 选项——那需要改导出栏 UI，超出"最小侵入"边界。
5. **参数锁定（lock）与撤销栈未实现。** PRD 的 §5.2 列了这两项；`LookPanel` 是项目既有组件，加锁定/撤销需要改它的状态管理。当前已交付的是：随机（Shuffle 按钮）+ 可输入种子以复现，这已覆盖"可复现"这个核心诉求。
6. **v2 扩展位（架构已预留，未实现）**：Voronoi 底场、Superformula 基元、L-system、Moiré 专用调制。

## 八、方法论说明（为什么这份报告敢说"验证过"）

本次最有价值的经验是一条：**不要问模型"这样好不好看"。**

调预设时我反复用视觉模型评审，它**连续三轮报告同样的缺陷**（"太稀/太散/像噪声"），而底层元素数明明从 64 涨到了 312。原因有二：一是 1000px 的图被压进 ~100px 的缩略格，细节全丢；二是我的提问本身带引导性。

改用三条客观手段后才真正收敛：

1. **覆盖率**（图形面积 / 画布面积）
2. **分带走向**（把画布切成 10 条横带，看覆盖率分布，判断渐变方向是否符合设计意图）
3. **连通率**（弧跨度 / 单元间距，<0.85 就是"够不到邻居"）

加上与参考图的**像素级密度比对**，最终从"5 个预设偏差 20~60 个百分点"收敛到"14/14 一致、平均误差 1.8 个百分点"。

还发现自己的比对脚本有个**极性 bug**（参考图有的黑底有的白底，我一律取"较小值为墨"，比错了方向），修正后才排除掉一批假警报。

以及最后一条：当评审说"等轴测迷宫像随机墨块"时，我把 SVG 里的线段抽出来量——353 条、长度全部 38.3、角度正是 30°/90°/150°、单一 19px 线宽。几何既然干净，问题就在观看尺度。把同一张图按自然尺寸打开，评审立刻改口为"Y 形节点约 120°、严格几何化、不是不规则墨块"。

这套方法已固化成 skill `visual-output-verification`，下次不用重新踩。
