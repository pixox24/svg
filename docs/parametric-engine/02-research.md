## 1. 技术谱系：八个算法家族

引擎的六个正交维度（Lattice / Modulator / Primitive / Transform / Topology / Palette）不是凭空设计，而是从这些既有算法家族里抽象出来的。

| 家族 | 核心规则 | 视觉产出 | 引擎中的落点 |
|---|---|---|---|
| **Truchet 瓷砖** | 方形瓷砖上的图案**不具旋转对称性**；平铺后由每块的朝向形成连续路径。Wikipedia 明确指出其朝向可用来"可视化信息"，即**朝向就是数据通道** | 连续通道 / 迷宫 / 编织纹 | `topology.mode = truchet`（参考图 01 / 14） |
| **Phyllotaxis 叶序** | 植物叶片排列；离散模型为 Vogel 公式 `θ = n·α`、`r = c·√n`，`α` 取黄金角时点分布最均匀且自然浮现斐波那契螺旋臂 | 向日葵盘式螺旋点阵 | `lattice.type = phyllotaxis`（参考图 05 / 13） |
| **黄金角** | 按黄金比分割圆周所得较小角 ≈ 137.5°。无理数特性使连续旋转永不重复 → 均匀且无可见方向性 | 叶序 / 消除放射状伪影 | `modulator.type = golden`、`lattice.divergence` |
| **Superformula** | Johan Gielis 于 **2003** 年提出，是**超椭圆（superellipse）的推广**，可用单一公式描述自然界大量复杂形状轮廓 | 花瓣 / 星形 / 有机多边轮廓 | `primitive.type = curvePoly` 的曲率参数（可视为超椭圆的离散近似） |
| **Perlin 噪声** | Ken Perlin 于 **1982** 年提出的**梯度噪声**；用于程序化生成地形、纹理、以及"对变量施加伪随机变化" | 有机流动、非重复的疏密变化 | `modulator.type = noise`（fBm 多八度叠加）+ `topology.warp`（参考图 03 / 07 / 10） |
| **Guilloché / 万花尺** | 通过"engine turning"机械雕刻出极精密、繁复、重复的图案；使用 rose engine lathe 等机床 | 钞票/证券底纹、同心缠绕线 | `lattice.type = ring / spiral`（参考图 08） |
| **Moiré 干涉** | 当两层带透明间隙的规则条纹叠加时产生**大尺度波干涉图样**，前提是两图案"不完全相同" | 放大、闪烁、伪立体 | `lattice.gap` 为负（重叠）+ 半径/尺寸梯度（参考图 02 的四角星负空间） |
| **Voronoi** | 把平面划分为"到各给定对象最近"的区域，本质是一种**镶嵌（tessellation）** | 细胞、裂纹、有机网格 | v1 未实现；列为 v2 候选（与 `lattice` 维度天然兼容） |

**关键推论**：参考图里出现最多的是 **Truchet（连通）**、**Vogel/黄金角（叶序）**、**噪声调制**、**Moiré 式重叠**——这正是引擎 v1 优先覆盖的四条。Superformula 与 Voronoi 是明确的后续扩展位，架构上不需要改动管线。

## 2. 美术史锚点：这些图形从哪来

| 人物 | 身份（Wikipedia 取证） | 与"参数化"的关系 |
|---|---|---|
| **Victor Vasarely**（1906–1997） | 匈牙利-法国艺术家，被广泛认为是 Op Art 运动的「祖父」与领袖 | 他用**有限几何单元的规则变形**制造视觉张力——把"单元 + 变换"作为创作方法，正是参数化思维的先声 |
| **Bridget Riley**（1931– ） | 英国画家，以 Op Art 绘画闻名 | 代表作 *Movement in Squares*（1961）通过对同一单元的**连续参数变化**（方形被逐步压扁）制造运动错觉——这是"一个参数扫过整个画面"的最纯粹示范，直接对应引擎的 `modulator` 维度 |
| **Op Art 运动** | Wikipedia：这是一种使用被扭曲/操纵的几何图案来制造视错觉的风格；**"Op art" 一词始于 1964 年**，1960 年代尤其流行（1965 年 MoMA 展览 *The Responsive Eye* 是标志事件） | 说明"用规则几何制造强视觉效应"是有明确历史血统的成熟语言，不是随机的装饰 |
| **Zdeněk Sýkora**（1920–2011） | 捷克抽象画家与雕塑家，**在艺术中使用计算机的先驱** | 他把计算机引入绘画结构生成 → 图形由**程序 + 参数**而非手感决定 |
| **Vera Molnár**（1924–2023） | 匈牙利媒体艺术家，被广泛认为是**计算机艺术中生成艺术方面的先驱**，最早在美术实践中使用计算机的女性之一；1960 年代在法国创立了两个艺术团体 | 她著名的"微小的系统性扰动"（同一构图做极小幅规则偏移）直接对应引擎的 `topology.jitter` 与 `modulator.phase` |
| **Georg Nees**（1926–2016） | 德国学者，**计算机艺术与生成图形的先驱** | 与 Nake、Noll 等共同奠定"算法即作者"的传统 |

**对产品的意义**：参考图的美学不是无来由的——它落在 **Op Art（1960s）+ 早期计算机艺术（1960s–70s）** 这条脉络上。引擎把这条脉络的**手法**（单元 × 参数扫掠 × 系统性扰动 × 图底反转）变成可调滑杆，等于让设计师直接操作一套有历史有效性的视觉语法。这一点应当写进产品的对外说明里——**这是"为什么这些图形看起来高级"的答案**。

## 3. 竞品与同类工具

> 说明：本节基于 `[领域知识]`（本机无搜索后端，未做在线取证）。竞品的**具体功能细节可能已变化**，实施时若需对外宣称差异化，应重新核验。

| 工具 | 形态 | 参数控制 | 导出 | 定位 |
|---|---|---|---|---|
| **CSS-doodle** | 代码驱动的 CSS 生成图案库 | 手写 DSL，无参数面板 | 输出 SVG（generator API） | **本项目已用**；面向会写代码的人 |
| **Tabbied** | 生成式图案库 + 参数对象 | `createPattern(host, config)` 传参 | `exportSvg()` | **本项目已接入**，是"第三方引擎接入"的完整范例 |
| **Paper.js / p5.js** | 通用创意编程库 | 全靠写代码 | Canvas / SVG | 面向开发者，非设计师 |
| **Haikei** | 在线生成器集合（波浪、斑点等） | 少量滑块 | SVG / PNG | 单图形态，**无参数组合、无种子、无预设体系** |
| **Blobmaker** | 在线 blob 生成 | 少量滑块 | SVG | 单形态，极窄 |
| **Magic Pattern / Hero Patterns** | CSS 背景图案库 | 基本只有颜色 | CSS / SVG | 静态图案库，**不可参数化** |
| **Subform / Rive** | 专业参数化布局 / 交互动画工具 | 复杂参数系统 | 多格式 | 面向 UI 布局与动画，不是几何图案生成 |

### 竞品共性缺口（这是差异化机会）

遍历后可以确认的**共同缺口**：

1. **参数面板组织**普遍是"十几个平铺滑块"，**没有维度分组、没有逐步引导**，新手不知道从哪个开始动
2. **绝大多数没有种子（seed）机制** → 随机出好结果**无法复现**，这是创作工具里的致命伤
3. **没有"锁定 + 局部随机"** → 只能全随机，无法保留已满意的部分
4. **预设是静态图片**，不是"参数快照" → 无法从预设出发继续演化
5. **导出选项单薄**（常常只有 PNG），缺乏 SVG 矢量导出与参数分享链接
6. **参数之间是孤立的**，没有"底场 × 调制 × 基元"这种**可组合的语义结构** → 用户只能换图案，不能改变生成逻辑

**本引擎的差异点（可直接写进宣传）**：
> 不是"图案库"，而是**可组合的参数管线**——底场 × 调制 × 基元 × 拓扑，六维自由组合；随机可复现（种子）；可锁定局部再随机；预设是参数快照可继续演化；导出 SVG 矢量与参数分享链接。

## 4. 设计工具的交互惯例（可落地清单）

> `[领域知识]`，来自 Figma / Blender 节点 / After Effects 等专业工具的通行做法。

**参数面板**
1. **分组 + 折叠**：维度分组（本项目 6 组），默认只展开前 1–2 组，避免一次面对 40 个控件
2. **滑杆 + 数值输入并存**：滑杆负责探索（粗调），数值负责精确（复现/交接）
3. **条件显示**：只显示当前选择下有效的参数（如选了"螺旋"才显示圈数）→ 面板永远不出现无效控件
4. **一键复位**：双击标签恢复该项默认值；面板顶部有整体 Reset
5. **每组参数有中文标签**，不用 `frequency` 这类术语裸奔

**随机与种子**
6. **种子可见、可输入、可复制** → 好结果可复现，这是专业工具的底线
7. **锁定 + 局部随机**：锁住满意的参数，只随机其余
8. **随机结果必须"有内容"**：随机到空白/糊成一团会让用户失去信任（本引擎已在 `randomize()` 里内置可用性约束）

**性能预算**
9. **实时预览 ≤150ms** 的感知阈值；参数拖拽过程中不能卡输入
10. **元素越多越要节流**：按元素数自动降采样预览，导出仍用全量

**导出**
11. 至少 SVG（矢量，设计稿用）+ PNG（多倍率）+ 复制代码 + **参数分享链接**
12. 导出文件名要能自解释（预设名 + 种子）

**撤销**
13. ≥50 步参数撤销栈（⌘Z / ⌘⇧Z）。设计师会大量试错，没有撤销等于不敢调

## 5. 视觉复杂度与审美：为什么这些图"高级"

`[领域知识]` + 对 14 张参考图的观察交叉印证：

1. **高对比二值化**：14 张里 13 张是黑/白（或黑/浅色）双色，去掉色彩干扰后视觉注意力全部落在**结构与节奏**上。色彩只作为**单一锚点**出现（参考图 08 的黑底亮橙）
2. **简单规则 × 大规模重复**：单条规则极简（画圆、画线），但重复次数足够多 → 产生"图案感"而非"涂鸦感"。这是生成艺术公认的"简单规则，复杂结果"
3. **参数梯度 —— 让静态图形产生时间感**：半径/尺寸/密度沿某一轴连续变化，静态画面被读成"正在变化"→ 产生运动与纵深感（参考图 02 / 05 / 08 / 10 / 12 全部依赖这一点）
4. **图底反转（figure–ground）**：正负形面积接近时，视觉会在"白形"与"黑形"之间反复切换 → 闪烁、抖动、伪立体。这是 Op Art 的核心机制
5. **负空间是被设计的主角**：参考图 02 的四角星、图 04 的三叉星形**都不是画出来的**，而是形状排列后**留出来的**。设计师需要理解"留白是输出物"
6. **尺度层级**：同一画面里元素尺寸跨度足够大（>3:1）时才有"呼吸感"；尺寸单一则呆板
7. **微扰让规则"活"起来**：完全规整显得机械，加一点系统性扰动（抖动、噪声位移）立刻显得有机且精致。但扰动量必须小（10%–25%），过量就成了缺陷
8. **裁切制造张力**：图形冲出画布边界（而非留边距完整呈现）会让画面显得是"更大世界的一角"

**这些手法必须成为引擎的"默认值"**——设计良好的默认参数本身就应当产出符合上述审美标准的图形，而不是要求用户先学会理论。

## 6. 对引擎设计的启示（调研 → 落地）

1. **保留六维正交结构**，并把它**暴露给用户**（面板分组 + 中文标签）——这是与"图案库"的根本区别，也是竞品最大的缺口
2. **种子机制是必备项而非加分项**：可见、可输入、可复现，且**随机必须保证有内容**
3. **锁定 + 局部随机**：让"随机"从赌博变成探索工具
4. **预设 = 参数快照**，不是静止图片；从预设出发可继续演化（本引擎 14 个预设全部是完整参数对象，天然满足）
5. **条件显示参数**：面板永不出现无效控件（`showIf` 已实现）
6. **调制的连续性优先于基元的丰富度**：参考图的美感主要来自**参数扫掠**，不是来自形状本身。所以 `modulator` 与 `warp` 应放在面板靠前位置、给出足够细的步进
7. **默认配色锁死高对比双色 + 单锚点**，把彩色交给强调色（accent）一个位置，避免用户随手调出廉价配色
8. **微扰作为显式参数暴露**（`topology.jitter` / `warp`），默认给 10%–20% 的小量，让"有机感"成为默认体验
9. **导出必须含参数分享链接**——设计师的协作场景需要"把这个效果发给同事"
10. **v2 扩展位（架构已预留）**：Voronoi 底场、Superformula 基元、Moiré 专用调制、L-system
